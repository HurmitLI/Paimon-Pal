# Paimon Pal 0.5.0 开发与验收报告

日期：2026-09-02
分支：`codex/electron-paimon-rebase`

## 1. 本阶段结论

本阶段不再把功能做成普通文件夹式窗口，而是以 MacBook 顶部刘海为固定入口：点击刘海后，工作区从屏幕顶部向下展开；派蒙对话框嵌入展开区右下角；派蒙也可以脱离刘海成为可拖拽桌面宠物，并可拖回刘海归位。

项目基于 xiaopu-ai 的 TO-DO Panel（MIT）重构，保留上游许可证和来源声明。派蒙角色视觉仅用于个人非商业课程作业，不作为可商业分发素材。

## 2. 已完成功能

### 刘海工作区

- 顶部刘海锚定、点击展开/收起、全屏可见与多屏定位。
- 首页、待办、笔记、链接、番茄钟、快捷录音、当前窗口、音乐控制、密钥和设置等上游工作台能力。
- 派蒙头像作为工作区内的助手入口；回答和输入框位于刘海展开区内部，不弹出屏幕中央大聊天窗口。

### 桌面派蒙

- 独立透明桌面宠物窗口，始终只保留一个实例。
- 支持拖拽、屏幕边界限制、位置持久化和重新启动后恢复。
- 拖回顶部刘海区域自动停靠并隐藏；从刘海再次放出时恢复为桌面宠物。
- 统一刘海出场、桌面待机和聆听状态的角色尺寸，避免重影与突然缩放。

### 本地智能与工具

- 内置 Qwen3 4B 4-bit 本地模型，默认离线运行，最多携带最近 6 条对话。
- 本地确定性工具：自然语言计时、添加今日待办、保存随手记、打开工作区页面。
- P1 本地 TTS，语音默认关闭，由用户在派蒙输入框中主动开启；输出前会去除机械重复的“旅行者”称呼。
- Paimon Pal 与上游 TO-DO Panel 使用不同的数据目录，不自动读取或解密上游密钥。

## 3. 隐私与权限边界

- 本地模型、本地 TTS、工作区和对话历史默认只在本机处理。
- 麦克风、摄像头、录屏和辅助功能仅在用户使用对应能力时申请。
- 不默认采集剪贴板，不自动上传对话、语音或桌面内容。
- 如使用联网模型，需要在 Paimon Pal 设置中单独重新填写密钥，不迁移上游应用的密钥。

## 4. 自动验收结果

- `npm test`：98/98 项 Node 测试通过，Electron 刘海焦点测试及全部 JavaScript 语法检查通过。

## 6. 已知边界

- 为保证完全离线，安装包内含 4B 模型和 TTS 运行时，因此应用约 6.1 GB、DMG 约 4.9 GB。
- P1 TTS 生成期间有一次性较高内存占用，完成后释放；语音默认关闭，不会常驻推理。
- 当前为 ad-hoc 本地签名，不是 Apple Developer ID 公证版本。换一台 Mac 首次打开时可能需要在“系统设置 → 隐私与安全性”中选择“仍要打开”。
- 当前角色动效使用现有有限帧素材；更高帧率、更多动作和更自然的转场属于后续视觉资产迭代，不影响本阶段功能闭环。
